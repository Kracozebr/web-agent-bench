# How to document this project

Document surprises, decisions, and evidence boundaries—not generic programming advice.

Every document should make clear:

- what is normative versus illustrative;
- which boundary produced the evidence;
- what is measured, what is inferred, and what remains unknown; and
- which command or artifact lets another agent reproduce the claim.

Keep stable project rules in `AGENTS.md`, behavior in OpenSpec, measurement semantics in
`docs/benchmark-protocol.md`, and change-specific decisions in the active OpenSpec change.
