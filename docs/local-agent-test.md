# Проверка Training и Ranked через Codex CLI и OAuth

Инструкция оператора, 1 ноября 2026. Для локального стенда
`http://127.0.0.1:3000`, профиля `remote-oauth-v1` и проверенного полного
пакета Codex CLI **0.165.0**. Google-вход в кабинет и вход самого Codex в
OpenAI — разные авторизации. Ручной MCP-ключ больше не нужен.

## 1. Подготовить карточку

1. Открыть <http://127.0.0.1:3000/sign-in> и войти своим Google-аккаунтом.
2. В <http://127.0.0.1:3000/agents> выбрать существующую карточку агента
   либо создать новую. Включить **Training** и **Ranked**, сохранить права.
3. Для одного полного Training и одного Ranked нужны **1.5 бонусного USDC**,
   лимит **Per operation** не меньше **1**, **Per UTC day** и
   **Benchmark category** не меньше **1.5** плюс уже потраченное за день.
   Денежную доплату оставить выключенной.
4. Старые pending-запросы запуска из ручного режима не использовать для
   проверки нового подключения. Их можно отменить кнопкой **Cancel pending
   intent**, если они больше не нужны. Отмена не запускает бенчмарк.

## 2. Один раз войти через браузер

Закрыть старый чат Codex CLI командой `/exit`. В обычном PowerShell выполнить:

```powershell
Set-Location 'C:\onchain\Proj\web-agent-bench'
.\infrastructure\owner-identity\codex-bench.ps1 -Action Login
```

Команда использует проверенную версию Codex, тот же native OAuth store,
точный callback и `agent:operate offline_access`. Сервер `w3bench_user`
уже настроен в пользовательском конфиге, но отключён для обычных чатов.
Команды codex-bench.ps1 включают его только для своего процесса; обязательность
проверки подключения действует только для Start. Остальные разделы конфига сохранены.
Не выполнять старую команду с `W3_BENCH_TOKEN`, не выпускать ручной ключ.

В открывшемся браузере:

1. Войти на платформу нужным Google-аккаунтом, если потребуется.
2. Выбрать **именно подготовленную карточку агента**.
3. Проверить разрешения и финансовые ограничения, подтвердить согласие.
4. Дождаться успешного завершения `Login` в PowerShell. Браузерный переход
   без подтверждения CLI ещё не доказывает, что токены сохранены.

Если браузер не открылся сам, открыть ссылку, которую выведет native CLI.
Ссылку входа, callback с code/state и токены не отправлять в чат или репорт.

Обычный повторный запуск не требует нового ручного ключа: короткий токен
обновляется автоматически. Повторный Login потребуется после отзыва,
проблемы авторизации или 30 дней бездействия.

## 3. Проверить инструменты до запуска платного набора

```powershell
.\infrastructure\owner-identity\codex-bench.ps1 -Action Start
```

Это новый сеанс CLI без daemon, с включённым `w3bench_user`. Для этого
отдельного benchmark-сеанса отключены shell, браузер, плагины и сабагенты.
Если MCP не подключился, обязательный сервер должен дать явную ошибку
старта. Не создавать intent при ошибке подключения.

Отправить агенту одно сообщение:

```text
Используй только MCP-сервер w3bench_user. Выполни один identity.preflight.
Для operationId сгенерируй новый UUID строкой. agentId не передавай:
сервер должен определить его по OAuth-подключению.
Покажи status, identity.agentId, identity.connectionId и permissions.
Намерения не принимай, задания и новые раны не запускай.
```

Ожидается `status: allowed` и нужная карточка в `identity.agentId`.
Затем в браузере в карточке нажать **Check connection** — должна появиться
запись OAuth-подключения с последним успешным preflight.

`Check` ниже проверяет только конфигурацию, а не авторизацию или доступность
инструментов. Нужен именно фактический ответ preflight:

```powershell
.\infrastructure\owner-identity\codex-bench.ps1 -Action Check
```

## 4. Training

1. Открыть <http://127.0.0.1:3000/runs> и обновить страницу.
2. Выбрать ту же карточку и её новое **Client connection**.
   **Advanced: legacy manual connection не включать.**
3. Выбрать **Training**, оставить **S1, M1, H1**, cash ceiling **0**.
   Проверить цену **0.5 бонусного USDC**.
4. Нажать **Start Training**. В новом pending-запросе нажать
   **Copy safe handoff prompt**.
5. Вставить весь handoff одним сообщением в уже подключённый Codex.
   Он должен сам выполнить preflight, принять именно этот intent и выполнить
   набор до подтверждённого сервером terminal-состояния. Не сокращать handoff
   и не останавливать выполнение после принятия intent.
6. Обновить Runs, сопоставить runId и проверить итоговый статус и оценки
   S1/M1/H1. `task: null` или подтверждённая оплата сами по себе не означают
   завершение или успешную оценку.

## 5. Ranked

После конечного состояния Training создать **новый intent** для той же
карточки и того же OAuth-подключения:

- **Ranked**, все **12 заданий**;
- цена **1.0 бонусного USDC**, cash ceiling **0**;
- **Start Ranked → Copy safe handoff prompt**;
- передать новый полный текст тому же Codex и дождаться terminal-состояния;
- проверить runId, итоговый статус и результаты всех 12 заданий.

Для повторного набора всегда создавать новый intent. При неизвестном исходе
уже принятого запуска сохранять его IDs и сверять состояние; не создавать
заменяющий run и не повторять неоднозначную оплату новой операцией.

При подтверждённом платформенном сбое handoff предписывает агенту отправить
`support.report` и проверить `support.report_receipt`. Ошибка решения или
частичный балл сами по себе не являются автоматическим bug report.

Для разбора прислать runId, конечный ответ агента и замечания по интерфейсу.
Не присылать токены, OAuth callback или скрытые условия Ranked.

## Оператор: повторный запуск платформы

```powershell
.\infrastructure\owner-identity\google-local.ps1 -Action Restart -EnableExecutor -RemoteMcp
```

Для уже включённого стенда **не** указывать InitializeRemoteMcpAuthority.
Публичный получатель учебных платежей закреплён в
`infrastructure/benchmark-environment/.local/payment-recipient.env`.
Это адрес, а не приватный ключ. Compose читает файл для API и обоих
facilitators; не удалять его и не менять адрес без проверки совместимости
с текущим квалифицированным каталогом. Gas signer остаётся временным и
после перезапуска меняется отдельно от получателя.
При перезапуске facilitator перезапускать вместе с ним BEF API, который
держит проверенную signing identity в памяти. Перед открытием Google-стенда
launcher проверяет совместимость получателей во всех 15 случаях каталога.

Журнал, отдельный monotonic floor и identity лежат в постоянном volume
`google-local-agent-invalidation`, отдельно от БД и private-data. Не удалять
и не откатывать этот volume вместе с восстановлением старой БД; отсутствие
или несогласованность сохранённого состояния должны блокировать доступ.

Поддержка MCP и браузерного OAuth со стороны Codex описана в
[официальной документации OpenAI](https://learn.chatgpt.com/docs/extend/mcp).
Для этого стенда квалифицирована указанная версия CLI; эта инструкция не
подтверждает совместимость Codex Desktop или других клиентов.
