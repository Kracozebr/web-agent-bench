# Review локального UI-прототипа

Дата: 23 октября 2026 года. Проверен [локальный прототип](../prototypes/mvp-ui/README.md),
подготовленный из последнего доступного интерфейса Stitch. Это ненормативный
дизайн-артефакт с синтетическими данными; результаты ниже относятся только к нему.
Авторизация, ledger, MCP, x402, chain execution и runtime gates не реализованы и
не проверены этим review. Исходный ZIP и SHA-256 сохранены в README прототипа.

## Результат

Основной UI-путь можно использовать для дальнейшего согласования и переноса
в приложение. Сохранено светлое оформление с indigo-акцентом; экраны, состояния
и данные разделены на редактируемые HTML/CSS/ES modules без внешних зависимостей.
Это ещё не набор Next.js/React-компонентов и не полный интерфейс всех функций MVP.

Luna/max подготовила реализацию; её запуск завершился по лимиту использования.
Основной агент выполнил отдельное ревью кода и браузерных путей, исправил найденные
ошибки и повторно проверил затронутые переходы.

## Исправленные замечания

| Область | Результат исправления |
| --- | --- |
| Соответствие MVP | Base/x402 обозначены как целевой симулированный контекст. Убраны вымышленные гарантии, сторонние сети и неподтверждённые интеграции. |
| Задания и расчёты | 12 заданий, веса 1/2/3/5, знаменатель ranked 26; восемь открытых заданий с весом 15; S3/M2/H3/U1 закрыты для training. |
| Результат | Fixture даёт 61.73%; Simple 92.5%, Medium 77.5%, Hard 54.4%, Ultra 25%. Значения, время и достигшая результата версия относятся к одному запуску. |
| Неизвестные наблюдения | Пропущенный, null или недопустимый credit не превращается в ноль и не получает rank. Явный подтверждённый ноль остаётся нулём. |
| Мастер | Исправлены заблокированная после ввода имени Continue, переключение способа подключения и восстановление черновика после выхода. Итог показывает права, cash fallback, лимиты и версию. |
| Необязательные метаданные | При сверке с ранее согласованным планом убрана обязательность client: доступны Not disclosed и продолжение без client/model. Это описание владельца, а не условие участия или гарантия совместимости. |
| Настройки | Новые права и cash fallback выключены. Сохранение снятого разрешения отменяет затронутый queued/preparing/active mock-запуск; неизвестный исход требует reconciliation. |
| Жизненный цикл | Free waiting intent отделён от run; queued/preparing удерживают сумму, старт списывает её один раз. Отмена до старта освобождает резерв; после старта сохраняет плату. |
| Возвраты и лимиты | Показаны возвращённые/освобождённые суммы по исходным источникам. Освобождённый или возвращённый платёж не продолжает расходовать демонстрационный дневной лимит. |
| Таймер | Исправлены незапущенный таймер в fixture отключения клиента и уничтожение подписи карточки при обновлении времени. Recovery pause и обычный disconnect различаются. |
| Публичность | Private route не раскрывает существование профиля; forum-only профиль может не иметь результата. Завершённый eligible ranked публикуется автоматически; ручной кнопки публикации результата нет. |
| Исторические данные | Изменение текущей объявленной версии не переписывает версию в выбранном результате и leaderboard. Равный score даёт равный rank независимо от времени. |
| Навигация | Мобильное меню имеет согласованные label/expanded; скрытое меню исключено из взаимодействия. Исправлен сброс aria-state панели сценариев; поля сохраняют фокус при перерисовке. |

## Выполненные проверки

Команда из корня репозитория:

```powershell
npm --prefix prototypes/mvp-ui run check
```

Пройдены syntax checks и domain smoke checks: состав задач, открытый набор,
полная и частичная цена, округление, рубрика fixture, unknown и score-only ranks.
Для S1 + H1 браузер показывает `ceil(500000 * 4 / 15) = 133334` micro-USDC.

Браузером проверены:

- мастер от sign-in/invitation до сохранения нового приватного профиля со всеми
  четырьмя выключенными правами; успешный бесплатный preflight не включает права;
- после сверки плана повторён полный мастер с Not disclosed для client, пустыми
  model/version: приватный профиль успешно сохраняется без раскрытия этих полей;
- отказ browser grant, переключение на synthetic token fallback и его отзыв;
  failed/pending preflight блокируют завершение; Save and exit сохраняет черновик;
- ranked quote → free waiting → acceptance → queued hold → preparing → start
  debit → 12 последовательных задач → coherent result и публичный профиль;
- копирование handoff: только service reference, mode и opaque launch ID;
- insufficient funds rejection до run/hold; состояния отмены до/после старта,
  queue expiry, platform failure/refund и unknown reconciliation;
- пауза при recovery и работающий таймер после disconnect; снятие ranked-права
  у активного запуска даёт Cancelled after start без публичного результата;
- private route, forum-only профиль без результата, leaderboard tie и сохранение
  достигшей результата версии после редактирования текущей версии;
- визуальный просмотр в iframe шириной 390 и 1440 px, мобильное меню и основной
  документ шириной 522 px: `scrollWidth == clientWidth`, повторных ID нет.
  В финальной браузерной сессии новых console warnings/errors не обнаружено.

Baseline tooling также пройдено:

```powershell
python -B tools/generate_bdd_mirrors.py --check
python -B tools/check_bdd_harness.py --json
```

Оба результата относятся к восьми baseline-сценариям: mirrors passed,
coverage complete, errors/warnings пусты. Это структурная проверка сохранности
baseline, не исполнение BDD активных MVP changes и не runtime-приёмка прототипа.

## Границы и дальнейший порядок

Основная инженерная последовательность не меняется: подготовка первого среза
→ feasibility среды → бесплатный сквозной путь → полный benchmark → платежи
→ форум/admin → приёмка пилота. Подробнее — [план реализации](mvp-execution-plan.md).
Предыдущая формулировка о переносе UI как следующем шаге была неполной: этот
перенос не заменяет этапы 0–1 и не разрешает начать продуктовую интеграцию в обход них.

1. Основной следующий шаг — `/opsx:explore benchmark-environment-feasibility`:
   конкретизировать manifest, инструменты, зависимости и guardrails; подготовить
   точный scope для review. Применение и gates — по согласованному OpenSpec workflow.
2. Параллельно просмотреть локальный основной UI-путь и согласовать визуальные
   детали. Дизайнерское согласование владельцем ещё не зафиксировано.
3. Подготовить принятые tokens/layouts к переносу в выбранный Next.js/React-стек.
   Оболочку и основной путь интегрировать на этапе 2 после feasibility и допуска
   соответствующих changes. Текущий mock-store не переносить как источник
   авторизации, баланса, billing или eligibility; повторить проверки на реальных
   ролях, API, БД, серверных часах и выбранных клиентах.
4. Баланс/пополнение/вывод и форум относятся к этапам 4–5; recovery/admin и
   операционные средства добавляются вместе со своими функциями. Общий ledger
   проектируется до интеграции бонусных или платных действий. Наличие прав на
   forum в мастере не означает готовый forum UI. Эти функции остаются в MVP,
   хотя текущий прототип их ещё не покрывает.

Численная pre-start policy в прототипе — явно помеченный пример на 10 минут.
Настоящий deadline определяется после queue/load validation. Денежный mock
использует агрегаты bonus/cash и не моделирует source lots, истечение каждого
grant, конкурентные транзакции или восстановление после серверного сбоя.
Browser tests не заменяют полный аудит accessibility, матрицу браузеров,
нагрузочные проверки или защиту публичных API. Runtime-статусы остаются `not_run`.
