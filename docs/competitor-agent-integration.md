# Подключение агентов у конкурентов

Дата исследования: 2026-10-22. Три агента Luna изучили восемь указанных проектов;
основной агент сверил ключевые различия с официальными страницами и исходниками.
Это исследовательский документ, а не нормативная спецификация или результат
интеграционного теста. Программы не запускались, аккаунты не создавались,
платежи не выполнялись. Ссылки на ветки репозиториев изменяемы: при реализации
нужно закреплять версии и коммиты.

## Подтверждённые решения нашего продукта

- Агент работает у владельца. Владелец запускает сессию; круглосуточный режим в
  первом MVP не требуется.
- Подключение через ссылку/инструмент существующего агента, без установки нашего
  коннектора. Удалённый MCP остаётся рекомендуемым интерфейсом.
- Все участники получают одинаковые тестовые инструменты. Проверяется решение
  задачи через них; это не доказательство собственной реализации кошелька/x402.
- Доступ охватывает бенчмарки, результаты, форум и другие выпущенные функции;
  будущие PvP и турниры используют ту же модель доступа, но не входят в MVP.
- Вывод USDC в MVP предназначен для человека через кабинет. Отсутствие инструмента
  вывода в MCP не доказывает человеческое действие: агент может управлять
  браузером владельца. Механизм подтверждения ещё не выбран.

## Сравнение восьми проектов

| Maxim | Многошаговые взаимодействия, ответы и качество интегрированного агента | Custom-агенты через код/HTTP; отдельно документированы Glean и Bedrock | SDK, API key, функция вызова HTTP endpoint или локального агента; есть собственные hosted workflows | Документированный SDK-путь требует кода. Прямое подключение готовых Claude/Codex/OpenClaw/Hermes по ссылке не установлено |

| BitGN | Действия агента в удалённом симулированном мире | Собственный агент/модель/framework через интерфейс runtime | Пользовательский Python sample, platform key, provider key, generated SDK | Проверенный quickstart требует локального проекта/кода, готовых клиентов по MCP не показывает |
| NexBench | Агентные действия в воспроизводимой fork-среде | JS step adapter или агент любого языка за HTTP `/step` | Локальный harness/CLI и адаптер или HTTP server | Самостоятельный harness/адаптер требуется; это не добавление инструментов в существующую сессию |
| alpha-arena.io | Заявляет торговое сравнение выбранных моделей | Перечислены модели, не готовые приложения агентов | Публичный leaderboard и waitlist; технический onboarding не раскрыт | Неизвестно |
| CyberChainBench | Detect/Exploit/Patch на случаях уязвимостей контрактов | Явно перечислены Codex, Claude Code, Gemini CLI, OpenCode | Локальный Docker/Harbor harness с CLI-адаптерами, ключами и RPC | Нужна подготовка среды; не внешний пользовательский агент по одной ссылке |

## Источники и существенные детали

### Maxim

[Продукт](https://www.getmaxim.ai/evals/products/agent-simulation-evaluation),
[HTTP SDK quickstart](https://www.getmaxim.ai/docs/offline-evals/via-sdk/agent-http/quickstart),
[local endpoint](https://www.getmaxim.ai/docs/offline-evals/via-sdk/agent-http/local-endpoint),
[local agent](https://www.getmaxim.ai/docs/offline-evals/via-sdk/local-agent),
[custom simulation](https://www.getmaxim.ai/docs/simulations/text-simulation/custom-simulation).

В изученном SDK-пути пользовательская функция вызывает агента и возвращает его
output/context; симуляции задают собеседника, цель и условия завершения.
Это оценка интегрированного агента, а не только модели. Наличие model/framework
интеграции не означает поддержку приложения Claude или Codex. В local-примере
используется ключ модельного провайдера пользователя; распределение всех расходов
во всех hosted/simulation режимах не установлено. Отсутствие универсального
бескодового входа не доказано: он не подтверждён изученными материалами.

### port402/x402-cli

[README и команды](https://github.com/port402/x402-cli).

`health` принимает URL; `--agent`/`agent` ищут A2A-карточки. `test` использует
локальную платёжную подпись. Нахождение карточки не доказывает запуск или оценку
агента. Есть preview/dry-run, предел суммы, пакетные проверки и JSON-вывод.
LLM-расходы к основной диагностике неприменимы. README показывает заголовок
`X-PAYMENT`; совместимость с выбранной версией x402 нужно проверять отдельно,
не копировать такой пример как контракт x402 V2.

### Settlens

Исходная страница `/product/assess` не извлеклась у исследующего агента; использованы
официальные [product](https://settlens.com/product),
[methodology](https://settlens.com/docs/methodology) и [MCP](https://settlens.com/mcp).

Assess выполняет детерминированные проверки endpoint. Методология отделяет
пассивные запросы без оплаты от специально разрешённой активной пробы.
MCP предлагает офлайн-проверки и сетевые инструменты с токеном; пример Claude Code
не равнозначен заявленной интеграции всех приложений. Проверка требований выдаёт
решение относительно spending policy, но сама не означает оплату и не оценивает
полный workflow агента. Точное размещение каждого сетевого worker не установлено.

### x402 Doctor

[Официальный README](https://github.com/Fizzl13/x402-doctor).

Web/remote MCP принимают URL без локального компонента на стороне пользователя.
MCP-диагностика может исследовать initialization, tools и неоплаченные вызовы.
Платные инструменты самого Doctor, диагностика целевого endpoint и отдельная
проверка доставки после оплаты — разные операции. Поддержка Claude/Cursor
означает доступ к инструментам Doctor; она не доказывает бенчмарк этих агентов.
Расходы и качество LLM целевого агента из такой проверки не следуют.

### BitGN

[Сайт](https://bitgn.com/), [quickstart](https://bitgn.com/start/PAC),
[main.py](https://github.com/bitgn/sample-agents/blob/main/pac1-py/main.py),
[agent.py](https://github.com/bitgn/sample-agents/blob/main/pac1-py/agent.py),
[dependencies](https://github.com/bitgn/sample-agents/blob/main/pac1-py/pyproject.toml).

Sample создаёт run/trial, получает URL runtime и инструкцию, локально вызывает
модель и инструменты, завершает trial и отправляет run. Агент и inference
остаются у участника, симулятор удалённый. CLI-приложения из нашего списка как
готовые подключения не перечислены. Provider оплачивает участник; автоматическая
сверка реального LLM-счёта не подтверждена. Есть подробный тренировочный feedback
и blind competition режим. Исследователь обнаружил различия значений по умолчанию
в quickstart, README и sample: будущая интеграция требует проверки версии.

### NexBench

[README](https://github.com/Nexis-AI/NexBench),
[agent tutorial](https://github.com/Nexis-AI/NexBench/blob/main/docs/tutorial-build-an-agent.md).

Контракт — `step(observation) -> action`: harness управляет циклом, временем и
условиями. Альтернатива JS-адаптеру — HTTP `/step`, включая Python server.
Закрытые prompts/weights остаются у участника. Inference оплачивается участником;
показанная примерная метрика cost/task не доказывает сверку provider billing.
README различает полный заявленный набор и небольшой исполняемый публичный
срез. Полезны манифест запуска, evidence, проверяющий и отдельные показатели
успеха, повторяемой надёжности и нарушений безопасности.

### alpha-arena.io

[Указанный сайт](https://alpha-arena.io/) перечисляет выбранные модели и заявляет
равные условия, публичные сделки и outputs. Собственный агент, SDK/MCP/API,
расположение исполнения и порядок технического подключения не раскрыты.
По landing нельзя подтвердить фактическую торговлю или результаты.

Идентичность с Nof1 не установлена: [официальный Nof1](https://www.nof1.ai/)
ведёт на `alphaarena.ai`, а не на указанный домен с дефисом. Поэтому сведения
разных доменов не объединяем. Указанная страница описывает Season 1 2025 года;
она не доказывает текущую доступность технического onboarding.

### CyberChainBench

[Сайт](https://defai-labs.github.io/CyberChainBench/),
[README/settings/architecture](https://github.com/defai-labs/CyberChainBench).

README разделяет agent/model setting. Указаны адаптеры codex, claude-code,
gemini-cli, opencode и контейнер с готовыми CLI и verifier. Поддержка нового
OpenAI-compatible model endpoint не означает готовую интеграцию нового агента.
Установка включает зависимости, Docker/Harbor, API keys и RPC; `web3mcp` не
используется в Codex exec mode. Контейнерный сетевой proxy нельзя считать
контролем сети нашего внешнего агента: у нас контролируются только серверные
инструменты и выданная среда.

## Дополнительный ориентир

[AgentBeats](https://docs.agentbeats.org/) отделяет участника от оценщика, использует
A2A для агентного взаимодействия и MCP для инструментов.
[Tutorial](https://github.com/RDI-Foundation/agentbeats-tutorial) требует запуска
агентных серверов; [remote guide](https://docs.agentbeats.org/Blogs/blog-3/)
описывает controller и публичный URL. Это полезный ориентир для будущего
программного подключения, но не подтверждение входа готового desktop-агента
без адаптации. A2A не предлагается обязательным условием нашего MVP.

## Вывод для нашей интеграции

Общая модель инструментов через удалённый MCP остаётся подходящим кандидатом
для выбранного пользовательского опыта. Это вывод из сравнения, а не измеренная
интероперабельность. Нужны клиентские проверки авторизации, запуска одной задачи,
разрыва соединения и списаний. Наличие клиента в списке моделей конкурента
не считается доказательством готовой интеграции приложения.

Для внешнего агента нельзя автоматически переносить свойства локального harness:
контроль времени, сетевую изоляцию, неизменность модели или измерение inference
cost. Проверять результат следует по состоянию нашей среды и журналу принятых
действий, сохраняя неизвестные измерения явно неизвестными.

## Решения пользователя по дополнительным механикам

Пользователь выбрал пункты 1–2 для MVP, пункты 3–6 для следующих этапов.
Это согласование объёма продукта; детальные спецификации и реализация впереди.

1. **В MVP.** Бесплатный короткий preflight подключения перед платным прогоном: проверить
   авторизацию и выполнить одну тестовую операцию. Развитие подхода диагностики
   endpoint; не утверждение, что конкурент так проверяет качество агента.
2. **В MVP.** Учебный и рейтинговый режимы: открытый feedback для обучения; отдельные
   закрытые варианты и правила публикации результата для лидерборда.
3. **Позже.** Сравнение версий собственного агента на одинаковых условиях с отдельными
   изменениями результата, скорости и нарушений правил.
4. **Позже.** Публикуемая по выбору владельца карточка прогона/воспроизведение принятых
   инструментальных действий. Без скрытых ответов, секретов, приватных prompts
   и внутреннего рассуждения агента. Не обещает повторяемость его LLM-решений.
5. **После базового набора задач.** Стресс-варианты: timeout после оплаты,
   временный сбой и восстановление. Позднее включение одобрено; точный этап,
   состав и оценка ещё не выбраны.
6. **Позже, после исследования.** A2A-вход для самостоятельно размещённых агентов
   по образцу AgentBeats; конкретное решение требует дальнейшего исследования.

Следующий шаг: `/opsx:explore` — определить границы заданий, сложность и оценку,
после чего подготовить отдельные OpenSpec proposals и BDD design.
