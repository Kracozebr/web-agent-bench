## Intent

Verify the actual trusted result/scoring/publication boundary and public/private
English pages. Public overall and four difficulty indicators must describe one
best eligible run within one benchmark version. Task grading, chain execution,
public replay, private tool journals and financial settlement remain outside scope. Ranked no-human-help policy disclosure and its limits are included; human-assistance detection/adjudication is not.

## Scenario design

All gates are mandatory `environment`, using actual TypeScript HTTP/application,
PostgreSQL, lifecycle/auth/forum integrations and real browser pages where named.
BLP-SC-001 requires the actual coordinator handoff. Controlled declared evaluator
fixtures may supply known credit fractions to test scoring; they cannot claim
actual x402/swap task validity. A Python formula model or fabricated event alone
does not replace these integrations.

- Proposed adapter module: `tests/bdd/adapters/benchmark_leaderboard_and_agent_pages.py`,
  exposing `benchmark_leaderboard_http_postgres_adapter` and
  `benchmark_pages_browser_adapter`. Reusable steps remain declarative.
- Required actual integrations: coordinator terminal handoff/store, verified
  identity/owner sessions, agent metadata/version snapshots, forum visibility,
  result consumer/scorer, public/private HTTP and Next pages, PostgreSQL and a
  supported browser. Use synthetic acceptance identities, not real owner data.
- Control concurrency, restart, delayed/lost responses and projection rebuild
  through private acceptance controls. Do not expose fixture or trusted-score
  injection on participant routes. Real task actions/payment are not replayed.
- Preserve source input hashes, event/result/selection/publication/version IDs,
  exact arithmetic inputs/results, sanitized response/DB observations and browser
  raw paths/hashes. Check public API, HTML, hydration/prefetch and cache behavior,
  not merely visible text. Credentials and owner private diagnostics stay out
  of public artifacts and public projection payloads.
- Missing integration, browser or named observation -> `blocked`; violated
  assertion -> `failed`. Mandatory blocked/skipped/not-run gates prevent
  sync/archive. All current statuses remain `not_run`.

## Confirmed version admission policy

New training and ranked requests target only the active benchmark version. Already admitted requests, including queue waiters, preserve pinned rules/environment/price and may finish after activation under existing authorization, expiry and cancellation rules. Identical authenticated retries resolve the existing request; new old-version requests create no run/reservation. Test authoritative activation/admission ordering, no retargeting/repricing and late results updating only their historical projection without changing original result snapshots. History reads are not execution authority and must not start an old node. This confirms the product policy, not the full scenario/implementation scope; all gates remain not_run.

## First-public-action review correction

BLP-SC-016/017 require actual AAP-managed profile records plus actual forum and
lifecycle transactions, including qualifying rollback/race/retry and a full
eligible all-zero result. The shared profile marker is checked on public API,
HTML, hydration/prefetch, embed and cache reads; private owner/agent operations
remain scoped separately. A declared controlled evaluator fixture is permitted
for this publication boundary only, with actual coordinator terminal integration;
it does not prove the task grades. Original marker identity and current forum
redaction/visibility survive rebuild and moderation. All seventeen gates are
not_run and still require full packet approval before executable implementation.
