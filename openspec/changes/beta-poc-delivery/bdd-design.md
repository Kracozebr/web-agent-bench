# BDD design packet: beta-poc-delivery

Workflow: [task-design](../../../docs/task-design.md).

**Status:** Approved for implementation and acceptance. **Decision:** approved on 28 October 2026. **Runtime:** all 26 gates `not_run`.

## Intent

Protect the bounded external journey: real Google owner, atomic code credit, four real model clients, isolated training/full12, private feedback, reports and target-host recovery. See [design](design.md) for profile and bounds. No real money, forum, full historical leaderboard, hosted model or whole-MVP acceptance is added; minimal anonymous public card/best-result views are included by the owner decision.

## Semantic harness contract

The JSON is review-only. After approval install its exact inventory in `tests/bdd/changes/beta-poc-delivery/harness-contracts.json` and add named mapper/adapter registrations and Gherkin mirrors through existing active-delta tooling. Proposal preparation does not install placeholder passes or edit main runtime contracts.

Every entry declares boundary, observations, negatives, effects and evidence mode. `allowed_private_calls` is empty: private fixture setup and independent read-only inspection may support a capture, but cannot replace the initiating owner/admin browser click or native-client action. Each real-model gate requires actual participant-owned inference; no deterministic provider substitutes.

## Execution design

- Reuse owner-web, owner-identity, BEF, the source ledger/evaluators, existing capture structure and independent `oid_observer` / `bef_observer` read-only transactions. The Codex deterministic Responses fixture is transport-only.
- Environment captures retain actual request/receipt/generation/action bindings, independent DB/chain observations and negative outcomes, sanitized raw paths/hashes and stable source/profile/client inventory.
- BPC-SC-014 covers all eight shared open tasks and single/multi selections. BPC-SC-009–012 each require one real-model training selection and full12; an eight-task training run per application is not added.
- Partial/zero solution grades are valid participant outcomes when verified grading and continuation complete. A platform unknown does not pass a positive client journey. BPC-SC-017 deliberately injects bounded platform-evidence failures and verifies retained unknown, original effects and exact refunds/fencing.
- BPC-SC-023 reads retained external bundles/operation records without network writes, verifying every required observation/variant and hash rather than status flags. Changed sources invalidate current readiness claims without rewriting history.
- Missing actual Google/host/RPC/client/model access or negative producer yields `blocked` with a precise reason when attempted; unattempted gates remain `not_run`. Mandatory skips block beta release, sync and archive.
- Planned commands after implementation inside the declared runtime: `python -B tools/generate_bdd_mirrors.py --change beta-poc-delivery --check`; `python -B tools/check_bdd_harness.py --change beta-poc-delivery --json`; `python -B tools/run_bdd_acceptance.py --change beta-poc-delivery`. This proposal adds no executable adapter and does not claim those beta runtime commands already pass.
- Source builds/static checks support but never close environment gates; a SQL fixture is not browser-to-database E2E. Preserve all old MVP evidence and gate states.

### Screenshot and 24-hour waiting evidence

BPC-SC-024 covers bounded image validation/normalization, private upload/attach/read,
wrong principal and bytes, response-loss retry, concurrent fourth attachment and
orphan cleanup. BPC-SC-018/019/020/022/026 additionally exercise owner/agent/admin and
restored screenshot surfaces. Retain normalized test-image hashes and observer
readbacks; use synthetic screenshots with no user secrets. Screenshot tests do
not require capturing a participant's desktop. Verify private image storage and
DB references independently, including absence after invalid upload/attach.

BPC-SC-016 must prove exactly 86400 seconds from original admission, including
just-before/at/after cases and restart/retry without renewing it or applying the
local 3600-second ceiling. Controlled fixture preparation of old admission times
may support the real request/worker/DB boundary; waiting 24 wall-clock hours is
not required and the fixture clock boundary must be recorded explicitly.

### Reconciled review findings

Qualification manifests allow real restricted evidence collection before client
profiles are verified; full cohort release still requires all four families.
BPC-SC-013 checks both stages. BPC-SC-016 tests expiry with a preparing generation
whose fence is unavailable, owner-visible pending cleanup and later original fence.
BPC-SC-024 includes MCP begin/chunk/finish frames and owner attachment fallback,
output/rolling/staging/disk quotas. Small synthetic images may supply exact test
bytes; do not fabricate a captured screenshot or leak bearer values through prompts.
BPC-SC-025 uses actual anonymous application reads on public projections under
controlled qualification network access, then verifies the same frozen release
handlers. BPC-SC-026 covers report content expiry from the recorded beta end,
failed purge retries and old-backup restore without resurrection. No erased report
body/image is required as permanent grading evidence.
