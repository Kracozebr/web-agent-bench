## Intent

**Goal:** Prove each retained rubric against actual isolated effects and connect those outcomes to the real lifecycle and leaderboard.

**Non-goals:** participant intelligence/autonomy, mainnet, hosted inference, supplied credit fixtures as task proof, new goals/weights, stress injection or replay UI.

## Semantic harness contract

`bdd-harness-proposal.json` is the approved inventory. Its runtime contract is registered in `tests/bdd/changes/benchmark-task-suite/harness-contracts.json`. Each scenario requires the named observations, negative variants and durable effects at its real boundary. Real adapters must precede execution; never sync a draft to bypass tooling.

## Execution design

- Reuse actual environment/tool/lifecycle/ledger boundaries and real result/leaderboard consumers.
- Add named mappers and one public-surface adapter only after approval. No private solver/grader calls; record actual x402/token/receipt/delivery and store provenance.
- Bind complete validated cases, actual application and the selected isolated EVM/settlement. Missing fork, SDK, fixtures or observations blocks the corresponding gate, never a Python model substitute.
- Scoped reference-driver execution proves mechanics, not external-agent reasoning or Base mainnet. Separate client compatibility evidence remains in access planning.
- Read-only reconstruction detects divergence without new actions, charges, refunds or score overwrite.
- Keep closed cases out of public artifacts and reusable payment payloads out of logs. Retain controlled raw paths/hashes without keys or real user data.

## Approval boundary

Approval covers these 34 scenarios, actual public-surface adapter, catalog/evaluator/projection and coordinator integration in isolated test funds. Real payments, external broadcast, model calls and public fixture publication are excluded. New scenarios or changed assertions return to review.
