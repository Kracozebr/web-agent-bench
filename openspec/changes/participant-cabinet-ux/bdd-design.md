## Intent

**Goal:** Participant cabinet and actionable diagnostics. Owns authenticated presentation and owner-context actions. ACI owns installer/refresh/handoff; BER owns execution truth; PBD owns anonymous publication; BTB owns timing policy.

**Non-goals:** New financial arithmetic, prices or refund authority; a general trace/journal product; live Ranked coaching; changes to public eligibility; installer/refresh implementation; or weakening API authorization.

## Semantic harness contract

Install the approved per-scenario entries into `tests/bdd/harness-contracts.json` only in a later apply. Every required observation and negative variant must have an independent replay derivation from raw capture, explicit outcome and missing-evidence handling. Producer counters or assertions alone are not sufficient. A variant not exercised keeps its mandatory gate non-passing. Stable IDs in the old BRL/BTS/BPC/AAP packets remain; integration extends those proofs rather than renaming old scenarios or resetting their status.

## Execution design

- Reuse current release validation, owner acceptance, native MCP, feedback/report/image, public-result, recovery and unified backup adapters only where the real named boundary and observations match. Add narrowly scoped new capture/replay bindings for uncovered behavior after approval.
- Browser journeys must initiate the actual business action through the running UI, followed by backend/worker and independently correlated PostgreSQL/BEF/file results. Direct API mutations, DOM/toast checks, intercepted success, localStorage and setup fixtures do not count as the user E2E.
- Native installer/client scenarios execute the actual OS/client path; no synthetic client or reference worker can establish participant-owned model acceptance. Record edition, version, protocol, model provenance and account availability separately; never record secrets.
- Each capture records source/build/profile, environment identity, run/operation/cutoff and causal order, raw artifact paths/hashes and independent observer. Raw business evidence is preserved privately under existing retention/backup rules; checked-in material is sanitized metadata only.
- Read-only replay cannot dispatch task commands, reset clocks, change grants/ledger/results, or mint refunds. A hash/binding mismatch is failed or unknown as appropriate, not an overwritten success.
- Missing target, native edition/model access, immutable pins, observer or required variant means `blocked` with reason; unattempted gates remain `not_run`. Distinguish `failed`, `skipped` and `passed`; skipped/blocked mandatory gates prevent sync/archive.
